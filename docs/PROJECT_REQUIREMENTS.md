# 插图 + 文字故事阅读系统：需求与设计基线

> 本文档用于跨电脑、跨开发工具持续开发。任何需求、范围或核心模型的变更，都应同步更新本文档。
>
> 文档状态：需求基线 v0.1（2026-08-12）

## 1. 项目目标

建设一个以“插图 + 文字”为主要呈现形式的故事系统，包含管理端和使用端。未来允许加入视频内容。

- 管理端：维护完整故事设定、组织创作内容与素材，并在统一设定约束下通过 AI 辅助生成故事和图片。
- 使用端：面向普通读者，公开浏览、筛选、预览和阅读故事，并查看或下载允许公开的 CG。

仓库采用四项目结构：

- `story-admin-server`：管理端 Java 后端
- `story-admin-web`：管理端 Vue 前端
- `story-user-server`：使用端 Java 后端
- `story-user-web`：使用端 Vue 前端

## 2. 核心设计原则

### 2.1 设定具有继承层级

```text
系列全局设定
  ↓ 必须遵守
篇章局部设定
  ↓ 必须遵守
章节 / 场景设定
  ↓
AI 生成文字、插图及未来的视频
```

篇章可以补充系列设定，但不能静默违背上级设定。发生冲突时，管理端应提示管理员选择“修改全局设定”或“登记为剧情例外”。

### 2.2 创作资料与公开资料分离

详细设定、AI 提示词、剧情秘密等仅供管理端和 AI 创作使用；使用端只展示明确标记为公开的信息。人物等资料应支持公开简介、内部设定和剧透信息的区分。

### 2.3 内容采用可扩展的内容块

故事页面不固定为“一张图 + 一段文字”，而由可排序的内容块组成，首期支持标题、正文、对话、插画和分隔内容，未来可加入视频、音频、动画和人物卡片。

### 2.4 AI 生成必须可追溯

保存生成时使用的上下文、模型、参数、提示词、原始结果、人工修改及版本状态。必须能区分 AI 原稿、人工修改稿、当前采用稿和已发布稿，并支持历史比较与恢复。

## 3. 管理端需求

管理端是带有 AI 约束能力的故事创作和资产管理平台，而不是简单的文章发布后台。

### 3.1 故事系列

系列是最高层级，包含：

- 名称、简介、封面、题材、主题标签和目标读者
- 整体世界观、时代背景和世界运行规则
- 社会制度、科技、魔法或能力体系
- 整体文风、叙事视角和语言风格
- 内容限制、创作禁区和 AI 生成约束
- 故事主线、最终目标及整体时间线
- 核心人物、地点、组织、种族和物品
- 连载、完结、草稿、已发布等状态

### 3.2 世界设定库

每个系列拥有独立设定库，包括：

- 人物及人物关系
- 地点及地点关系
- 组织、阵营、种族和生物
- 关键物品
- 能力、魔法或科技体系
- 历史事件和世界时间线
- 专有名词与术语

人物档案可包含外貌、身份、年龄、性格、语言习惯、动机、目标、能力、弱点、人际关系、成长轨迹、禁止行为及图片参考素材。

### 3.3 篇章、章节、场景和故事页面

- 篇章隶属于系列，继承系列设定并可拥有局部人物、背景、故事线和约束。
- 篇章记录标题、简介、封面、目标、开始与结束状态、出场人物、地点和时间范围。
- 篇章下划分章节，章节下可划分场景。
- 场景记录时间、地点、人物、目标、事件、情绪、前置状态、结束状态、正文和插图描述。
- 最终阅读内容由故事页面及其可排序内容块组成。

### 3.4 素材管理

素材包括系列/篇章封面、人物立绘与表情、服装参考、地点参考图、场景插图、物品图片、CG、AI 生成图片、用户上传图片、提示词模板，以及未来的视频素材。

每项素材应记录：

- 来源、文件类型、版本和版权说明
- AI 模型、提示词及生成参数（如适用）
- 关联的系列、篇章、场景、人物或地点
- 是否公开、是否属于 CG、是否允许下载、是否涉及剧透

文件本身存储于文件系统或对象存储，数据库保存地址和元数据，不直接存放大型图片或视频二进制。

### 3.5 AI 创作工作流

1. 读取系列全局规则。
2. 读取篇章局部设定。
3. 读取场景涉及的人物、地点和时间线。
4. 读取前文摘要和人物当前状态。
5. 检查设定冲突。
6. 生成大纲、正文或插图提示词。
7. 管理员审核、修改、采用或重新生成。
8. 依据确认内容生成插图，未来可生成视频。
9. 保存生成记录与版本。
10. 审核通过后发布给使用端。

### 3.6 管理端页面规划

- 管理概览
- 故事系列管理
- 世界设定库
- 人物、地点、组织、物品和术语管理
- 故事线与时间线管理
- 篇章、章节、场景和故事页面编辑器
- AI 文字创作工作台
- AI 插图生成工作台
- 素材与 CG 库
- 版本、审核和发布管理
- AI 模型与提示词配置

## 4. 使用端需求

首期默认全部公开，不考虑登录、用户权限、付费、收藏或评论。

### 4.1 故事发现与筛选

- 展示推荐、最新、热门故事及系列基本信息
- 按故事名称、关键词、主题、题材、标签、主角、世界观类型、更新状态筛选
- 提供“浏览主角”入口：主角列表 → 公开人物详情 → 所属系列和相关篇章

### 4.2 系列和篇章预览

- 系列封面、名称、公开简介和公开世界观
- 主角及主要人物、主题标签、公开 CG 和更新状态
- 篇章封面、简介、顺序、章节数量和发布时间
- 开始阅读及未来的继续阅读入口

### 4.3 图文阅读器

- 按页面或场景展示插画、文字描述和人物对白
- 上一页、下一页、章节目录、阅读进度和全屏展示
- 内容块按管理端配置的顺序呈现
- 数据模型预留视频内容块，视频不纳入首期开发

### 4.4 CG 图鉴

- 按系列展示 CG 缩略图
- 按篇章、人物、地点或主题筛选
- 大图、全屏、上一张/下一张和图片说明
- 仅当素材被标记为公开且允许下载时提供原图下载
- 剧透 CG 应具备隐藏或提示能力

## 5. 核心业务关系

```text
故事系列
├── 世界设定
├── 人物 / 人物关系
├── 地点 / 地点关系
├── 组织 / 物品 / 术语
├── 故事线 / 时间线
├── 篇章
│   ├── 篇章局部设定
│   └── 章节
│       └── 场景
│           └── 故事页面
│               └── 可排序内容块（文字 / 对话 / 插画 / 未来视频）
└── 素材库
    ├── CG
    ├── 人物素材
    ├── 场景素材
    ├── 物品素材
    └── 未来视频素材
```

## 6. 首期开发范围（MVP）

1. 管理端创建和维护故事系列。
2. 录入世界观、人物、地点和基本设定。
3. 创建篇章、章节、场景和故事页面。
4. 上传插画并编排图文内容块。
5. 审核并发布故事。
6. 使用端按主题或主角筛选系列。
7. 查看系列详情、篇章列表并阅读图文内容。
8. 浏览和下载被允许公开下载的 CG。

首期不包含：登录权限、付费、收藏、评论、复杂推荐、正式 AI 生成接入和视频生成/播放。数据结构应为 AI、视频和权限扩展预留空间。

## 7. 后续设计工作

- 设计数据库实体关系、继承/引用方式和版本模型
- 定义草稿、审核、发布、下线等状态流转
- 定义管理端与使用端 API 边界
- 选择数据库、对象存储及 AI 模型接入方式
- 设计 AI 上下文组装、摘要、冲突检测和成本控制方案
- 明确 CG 下载规格、图片压缩及水印策略

## 8. 尚未确定的事项

以下内容尚未定案，开发时不得自行假定：

- 数据库类型及部署方式
- 图片/视频对象存储方案
- 首批接入的文本与图片 AI 模型
- 故事的审核角色与具体发布流程
- “热门”和“推荐”的计算规则
- 剧透内容的解锁方式
- 视频功能的具体阶段和格式
- 后续用户账户、权限和商业化方式

## 9. 文档维护规则

- 已确认需求写入相应章节。
- 尚未确认的想法写入“尚未确定的事项”，不可表述为既定功能。
- 范围变化时同步修改“MVP”和相关功能章节。
- 数据库及 API 设计完成后，在 `docs/` 下新增专项文档，并在本文档中添加链接。
- 每次修改应使用能说明需求变化的 Git 提交信息。
