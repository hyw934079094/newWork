# 人物本体与多形态设计说明

> 状态：已实现（首期）  
> 日期：2026-08-13  
> 分支策略：在 `master` 上实现

## 1. 背景与目标

多数人物只需一条独立档案。部分角色存在「同一人、多种形态」（如日常 / 怪盗）：形态名称、设定、素材不同，但仍是同一个人。

目标：在管理端引入**人物本体**，把多个独立人物档案映射为同一人；本体可挂共用素材，形态人物仍各自挂素材并参与出场 / AI 引用。

## 2. 已确认决策

| 项 | 决策 |
|----|------|
| 形态是否独立人物 | 是；各自编号、设定、素材 |
| 绑定方式 | 单独实体「人物本体」；形态挂到本体下 |
| 普通人 | 不建本体，`identity_id` 为空，行为不变 |
| 后期加形态 | 在原独立人物上「添加形态」：自动创建本体，并关联原人物 + 新建形态人物 |
| 数据落地 | 本体表 + 人物表可空 `identity_id`（方案 1） |
| 一个人物多个本体 | 本期不做 |
| 通用关系网（亲属/敌友） | 本期不做 |
| 使用端聚合 / 剧透揭示 | 本期不做 |

## 3. 概念与数据模型

| 概念 | 说明 |
|------|------|
| 人物（形态） | 现有 `character_profile`：可出场、可挂设定/素材 |
| 人物本体 | 新实体：表示「同一个人」；可挂共用素材；本身不出场 |
| 无本体人物 | `identity_id` 为空 |

### 3.1 `character_identity`

| 字段 | 说明 |
|------|------|
| id | PK |
| code | 管理编号，唯一 |
| name | 本体名称（如「怪盗女孩」） |
| story_name | 所属故事/系列文本，可空 |
| public_intro | 公开简介，可空 |
| internal_note | 内部备注，可空 |
| created_at / updated_at | |

### 3.2 `character_profile` 增量

| 字段 | 说明 |
|------|------|
| identity_id | 可空 FK → `character_identity` |
| form_label | 可空，如「日常」「怪盗」，便于列表展示 |

约束：一个人物最多属于一个本体。

### 3.3 `identity_asset_rel`

| 字段 | 说明 |
|------|------|
| identity_id | FK → `character_identity` |
| asset_id | FK → `asset` |

主键 `(identity_id, asset_id)`。解除关联不删除素材文件。

## 4. 管理端界面

### 4.1 菜单

- 人物管理 → **人物** `/characters`（现有形态列表）
- 人物管理 → **人物本体** `/character-identities`

### 4.2 本体列表 `/character-identities`

列：名称、编号、故事、形态数、更新时间。  
操作：新建 / 编辑 / 删除（仍有挂接形态则 409）。

### 4.3 本体编辑

1. 基本信息：编号、名称、故事、简介/内部备注  
2. 共用素材：素材库选择或上传入库后再关联  
3. 映射形态：挂已有人物，或新建形态后自动挂接；可填 `form_label`、排序  
4. 形态卡片展示姓名、编号、标签、素材数量摘要  

### 4.4 人物列表微调

- 列或筛选「所属本体」；有本体时展示如 `怪盗女孩 · 日常`  
- 编辑人物时可选择所属本体（可空）；详情链到本体页  

### 4.5 典型操作流（先建本体）

1. 新建本体「怪盗女孩」，挂共用脸部/体型素材  
2. 新建人物「××（日常）」→ 挂本体，标签「日常」，挂日常素材  
3. 新建人物「怪盗××」→ 同一本体，标签「怪盗」，挂怪盗素材  
4. AI / 场景选人：仍选**具体形态人物**；可从本体页跳转各形态  

### 4.6 从独立人物升级为多形态（补充）

场景：起初只有一个独立人物（无本体）；后来要加怪盗等形态。

**入口**：人物详情 / 编辑页 → **添加形态**（仅当该人物当前 `identity_id` 为空时显示；若已有本体则走「在本体内再挂形态」）。

**一次操作完成**：

1. 自动创建人物本体  
   - `name` / `story_name` 默认取自原人物（可在弹窗中改本体名）  
   - `code` 按本体规则新生成  
2. 原人物挂上该本体，`form_label` 默认「默认」（可改，如「日常」）  
3. 按表单创建**新的独立人物**（名称、标签等），挂同一本体  
4. 跳转本体编辑页，便于继续挂共用素材或调整形态  

原人物已有的素材仍挂在原人物上，不自动搬到本体；需要共用的素材可事后在本体页勾选关联。

若原人物已有本体：该按钮变为「再添加形态」，只新建人物并挂到现有本体，不再新建本体。

## 5. API（`/api`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/character-identities` | 列表 |
| POST | `/character-identities` | 新建 |
| GET | `/character-identities/{id}` | 详情（形态摘要 + 共用素材） |
| PUT | `/character-identities/{id}` | 更新基本信息 |
| DELETE | `/character-identities/{id}` | 删除（无挂接形态） |
| PUT | `/character-identities/{id}/members` | 全量设置形态：`[{ characterId, formLabel, sortOrder }]` |
| PUT | `/character-identities/{id}/assets` | 设置共用素材 id 列表 |
| POST | `/characters/{id}/forms` | **添加形态**：无本体则自动建本体并挂原人物+新人物；已有本体则只新建并挂接 |

`POST /characters/{id}/forms` 请求体要点：

```json
{
  "identityName": "怪盗女孩",
  "originalFormLabel": "日常",
  "newCharacter": {
    "name": "怪盗××",
    "formLabel": "怪盗",
    "alias": null,
    "gender": null,
    "ageStage": null,
    "race": null,
    "occupation": null,
    "storyName": null,
    "publicIntro": null,
    "internalNote": null
  }
}
```

响应：本体详情（含水合后的形态列表）。原人物已有本体时忽略 `identityName`（沿用现本体），仍可用 `originalFormLabel` 更新原人物标签（可选；首期仅在新建本体时写入原标签）。

现有 `/characters`：请求/响应增加可选 `identityId`、`formLabel`；列表支持按 `identityId` 筛选。

## 6. 删改与引用规则

- 删本体：仍有形态 → **409**，消息含形态名；清空映射后方可删  
- 删形态人物：不删本体；清除该人物的 `identity_id`  
- 硬删素材：在现有人物 / 组合 / AI 检查外，增加本体共用素材引用 → **409** + 本体名  
- 解除本体-素材或形态-素材：不删文件  

## 7. 验收标准

1. 无本体时人物用法与现在一致  
2. 可建本体并挂 ≥2 形态（含 formLabel），刷新后配置仍在  
3. 本体可挂共用素材；形态可各自挂素材  
4. 有形态时删本体 → 409；硬删被本体引用的素材 → 409  
5. 人物列表能看出所属本体并跳转  
6. 独立人物点「添加形态」：自动生成本体，原人物与新人物均挂接，刷新后可从本体页看到两者  

## 8. 非目标

- 使用端「同一人」聚合页、剧透揭示  
- 通用亲属 / 敌友关系网  
- 形态之间自动合并 AI 提示词（仍按所选形态人物提交）  
- 一个人物挂多个本体  
- 添加形态时自动把原人物素材迁移为本体共用素材  

## 9. 实现顺序建议

1. Flyway：`character_identity`、`identity_asset_rel`、人物表增量字段  
2. Identity CRUD + members/assets API；素材硬删引用扩展  
3. Characters API / DTO 带上 identity 字段；`POST /characters/{id}/forms` 升级流  
4. 前端本体列表 + 编辑页；人物列表展示所属本体；人物页「添加形态」弹窗  
5. 联调验收  

## 10. 开放问题（不阻塞）

- 本体 `code` 是否与人物 `code` 共用一套生成规则（建议独立前缀，如 `ID-`）  
- `form_label` 是否做系统预设枚举（建议首期自由文本）  
- 自动建本体时，是否默认把原人物部分素材勾到本体（建议首期不自动勾，由管理员在本体页处理）
