## 1. 侧栏（已确认 · 方案 C）

### 规则

- **有多个真实二级页** → 可折叠一级 + 二级链接：故事管理、素材管理、人物管理。
- **单页入口** → 保持一级直达链接：概览、AI 参考区、回收站、系统配置。
- 不采用「无二级时点标题直达」的方案 B；不强制所有一级都带假二级。

### 现状对齐

当前 `App.vue` 已符合上述格局；本期**不提交侧栏代码变更**。

## 2. 页内拖拽与文图位置（已确认）

### 2.1 目标

1. 页编辑器时间线上的 **TITLE / BODY / DIVIDER / BEAT** 可 **拖拽排序**（可保留上移/下移作辅助）。
2. **BEAT 内部**：封面与正文/对白在同一列表中拖拽；文在图上 = 文节点排在封面节点之前。
3. 预览、篇章阅读流按 **数组顺序** 渲染，不再写死「上图下文」。

### 2.2 数据模型

#### 页级（不变）

`story_page.content_json` 仍为数组，顶层类型：`TITLE | BODY | DIVIDER | BEAT`。  
**数组顺序 = 视觉顺序。**

#### BEAT 新形态（规范形态）

```json
{
  "type": "BEAT",
  "coverAssetId": 123,
  "children": [
    { "type": "BODY", "text": "先看文案" },
    { "type": "COVER", "assetId": 123 },
    { "type": "DIALOGUE", "text": "再看对白" }
  ]
}
```

规则：

| 规则 | 说明 |
|------|------|
| COVER 子节点 | `type: "COVER"`，字段 `assetId`（必填，NORMAL 素材） |
| 每 BEAT 恰一张 COVER | 校验失败则拒绝保存 |
| `coverAssetId` 同步 | 保存时由唯一 COVER 的 `assetId` 写回 `coverAssetId`，供现有 `page_asset_ref(BEAT_COVER)` 与旧客户端兼容 |
| 子节点类型 | `COVER \| BODY \| DIALOGUE`；组内顺序自由 |

#### 旧数据兼容（读入规范化）

若 BEAT 仅有 `coverAssetId`、且 `children` 中无 COVER：

1. 在 **children 数组头部**插入 `{ type: "COVER", assetId: coverAssetId }`；
2. 其余子节点顺序不变（等价于旧版「上图下文」）；
3. 用户保存后即持久化为新形态。

若同时存在 `coverAssetId` 与 COVER 且不一致：以 **COVER.assetId** 为准，保存时回写 `coverAssetId`。

### 2.3 后端

**触点：** `PageService` 校验/收集封面；`ArcService.appendBeatSegments` 阅读流；相关单测。

**校验变更：**

- BEAT 必须含且仅含一个 `COVER` 子节点（规范化之后再校验，或保存路径先 normalize 再 validate）。
- `coverAssetId` 可仍要求存在，但必须与 COVER 一致。
- `BODY`/`DIALOGUE` 校验逻辑不变。

**阅读流：**

- 遍历 `children` **按序**输出：遇 COVER → IMAGE 段；遇 BODY/DIALOGUE → 文本段。
- **禁止**再「先强制 IMAGE 再扫 children」。

**无需新表/新迁移列**：仅 JSON 形态演进。

### 2.4 前端

**触点：** `PageEditor.vue`、`PagePreview.vue`（及嵌入它的 Arc 预览）、必要时共用类型/normalize 工具。

| 区域 | 行为 |
|------|------|
| 页级时间线 | `vuedraggable` 排序顶层块；手柄拖拽；可选保留上移/下移 |
| BEAT 展开区 | 独立 `vuedraggable` 排序 `children`（含 COVER） |
| COVER 行 UI | 显示缩略图 + 更换封面；不可编辑「文本」 |
| 预览 | 顶层与 BEAT 内均按数组顺序渲染；COVER 渲染为图 |

拖拽库：与素材工作台 / AI 参考区 / 组合编排一致，使用现有 **vuedraggable**。

### 2.5 非目标（本期不做）

- 左右分栏、多列、图文环绕。
- 页与页之间的跨页拖拽。
- 删除 BEAT 外壳、改为全页扁平流。
- AI 参考区故事/文案能力（见 §3）。

### 2.6 验收要点

1. 页级拖拽后保存刷新，顺序保持。
2. 组内把 BODY 拖到 COVER 上方，预览与阅读流均为「文 → 图 → …」。
3. 打开仅含旧 `coverAssetId` 的页，编辑器自动出现头部 COVER，预览仍为上图下文直至用户改序。
4. 保存缺 COVER 或两个 COVER 的内容被拒绝（或规范化失败有明确错误）。
5. 现有 `page_asset_ref` 仍正确指向 BEAT 封面素材。

## 3. AI 参考区（延期 · 仅占位）

用户意图：参考区以**故事/文案**为主，不仅是参考图。

本期不设计实现细节；实现完 §2 后另开规格，预期方向（非正式）：

- 引用类型扩展（素材 / 页正文片段 / 篇章摘要等）；
- 文案与故事可入篮、可排序；
- 与现有素材篮并存或迁移。

| 风险 | 缓解 |
|------|------|
| 旧阅读流/预览写死上图下文 | 同步改 `ArcService`、`PagePreview`、单测 |

| 拖拽与按钮双通道 | 共用同一数组，避免两套状态 |
