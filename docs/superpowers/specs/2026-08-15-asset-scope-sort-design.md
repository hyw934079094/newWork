# 素材工作台筛选作用域独立排序设计说明

> 状态：已实现（首期）  
> 日期：2026-08-15  
> 分支策略：在 `master` 上实现

## 1. 背景与目标

素材工作台在「人物=全部 + 无关键字」时，可拖拽缩略图改写分类内 `asset.sort_order`。一旦开启人物/系列/篇章等筛选或关键字搜索，本分类内排序被禁用，以免半集写回打乱「全部」视图。

业务需要：在固定筛选上下文下，缩略图仍可拖拽调整先后（例如把后面的拖到前面），且该顺序与分类全局顺序相互独立。

## 2. 已确认决策

| 项 | 决策 |
|----|------|
| 方案 | 方案 1：在各关联表增加 `sort_order`；「无关联」另表 |
| 作用范围 | 多种固定筛选各自独立顺序（人物 / 系列 / 篇章 / 无关联） |
| 关键字搜索 | 允许临时拖拽，**不持久化**；刷新后恢复 |
| 顺序粒度 | **当前分类** + 当前筛选作用域（同一人物在不同分类可有不同顺序） |
| 「全部」+ 无关键字 | 继续只用现有 `asset.sort_order` |
| 跨分类拖拽 | 行为不变；只改分类与分类全局顺序，不写 scope 顺序 |
| 首期不做 | 多选批量排序；搜索临时顺序一键落库 |

## 3. 存储

| 筛选上下文 | 顺序落点 | 作用范围 |
|------------|----------|----------|
| 人物=全部，无关键字 | `asset.sort_order` | 同一分类 |
| 具体人物 | `asset_character_rel.sort_order`（新增列，默认 0） | 同一人物 + 当前分类 |
| 具体系列 | `asset_series_rel.sort_order`（新增列，默认 0） | 同一系列 + 当前分类 |
| 具体篇章 | `asset_arc_rel.sort_order`（新增列，默认 0） | 同一篇章 + 当前分类 |
| 无关联 | 新表 `asset_unlinked_order` | 当前分类下无人物关联的素材 |
| 有关键字 `q` | 不落库 | 仅当前会话内存顺序 |

### 3.1 `asset_unlinked_order`

| 列 | 说明 |
|----|------|
| `category_id` | 分类 |
| `asset_id` | 素材 |
| `sort_order` | INT NOT NULL DEFAULT 0 |
| PK | `(category_id, asset_id)` |
| FK | 指向 `asset_category` / `asset`（级联或随素材删除清理） |

### 3.2 写入约定

- 新建关联（人物/系列/篇章）或素材进入「无关联」视图需落顺序时：`sort_order = 该作用域+分类下当前最大值 + 1`（无记录则从 0）。
- 解除关联、硬删素材、素材离开「无关联」集合时：删除对应顺序行或忽略孤儿。
- **禁止**在 scope 改序时修改 `asset.sort_order`。

### 3.3 关于「分类维度」

关联表 `(asset_id, character_id)` 本身跨分类唯一；同一人物可关联多个分类的素材。列表与改序均在**当前选中分类**内操作：只对「该人物 + 该分类」的关联子集读写 `sort_order`。跨分类比较时不保证单一全局人物顺序（首期可接受；人物管理页以返回列表顺序为准）。

## 4. 列表排序

`GET /api/assets` 在现有筛选（`categoryId`、`status`、`q`、人物/系列/篇章/linkType）不变的前提下，调整 **ORDER BY**：

| 当前筛选 | 排序键 |
|----------|--------|
| 人物=全部（或等价完整分类列表），无 scope 特化，无强制 scope 序 | `asset.sort_order ASC, asset.id ASC` |
| 具体人物 | 对应 `asset_character_rel.sort_order`，缺省回退 `asset.sort_order`，再 `id` |
| 具体系列 / 篇章 | 对应 rel `sort_order`，同样回退 |
| 无关联 | `asset_unlinked_order.sort_order`，缺省回退 `asset.sort_order`，再 `id` |
| 有 `q` | 先按「无关键字」规则排序/过滤；**不**因前端临时拖拽写库 |

说明：关联类型已选但未选到具体系列/篇章时，结果集不完整，UI 不允许持久化改序（见 §6）。

## 5. 改序 API

### 5.1 保留

`PUT /api/assets/reorder`  
body：`{ categoryId, orderedIds }`  
仅用于「全部 + 无关键字」；仍校验 `orderedIds` 等于该分类全部 NORMAL 素材；只写 `asset.sort_order`。

### 5.2 新增

`PUT /api/assets/reorder-by-scope`

```json
{
  "categoryId": 1,
  "scope": "CHARACTER",
  "scopeId": 12,
  "orderedIds": [5, 3, 9]
}
```

| 字段 | 规则 |
|------|------|
| `scope` | `CHARACTER` \| `SERIES` \| `ARC` \| `UNLINKED` |
| `scopeId` | CHARACTER / SERIES / ARC 必填；UNLINKED 省略或 null |
| `orderedIds` | 必须刚好等于「当前分类 + 该 scope」下可见 NORMAL 素材全集（唯一、非空）；写对应 scope 顺序字段为 `0..n-1` |

失败：参数不全、ids 不匹配、分类/作用域实体不存在 → 4xx；UI 回滚拖拽。

### 5.3 跨分类

`PUT /api/assets/{id}/move` 不变；不维护 scope 顺序（目标分类下该素材的 scope 序可在下次进入该筛选时按「追加到末尾」补齐，或列表时回退 `asset.sort_order`）。

## 6. 工作台 UI

| 状态 | 本分类内排序 | 持久化 |
|------|--------------|--------|
| 人物=全部，关联类型空，无关键字 | 允许 | `reorder` |
| 选中具体人物 | 允许 | `reorder-by-scope` CHARACTER |
| 选中具体系列 / 篇章 | 允许 | SERIES / ARC |
| 人物=无关联 | 允许 | UNLINKED |
| 关联类型已选但未选具体系列/篇章 | 不允许 | — |
| 有关键字 | 允许拖 | **不调**接口；提示临时 |

文案：

- 去掉「本分类内排序暂不可用，仍可拖到左侧其它分类」作为唯一提示。
- 按状态显示，例如：「当前按人物顺序排列，拖拽将保存到该人物」；搜索时：「搜索中顺序仅临时，刷新后恢复」。
- 跨分类拖到左侧其它分类的能力保持。

序号、上一份/下一份、缩略图选中：仍按**当前结果集**顺序（含临时搜索顺序）。

### 6.1 人物管理页

人物关联素材列表（含立绘预览）：若接口按人物返回资产，顺序应尊重 `asset_character_rel.sort_order`（同分类内）；跨分类展示顺序首期跟随查询默认（可按分类分组或 `sort_order` + `id`）。不要求人物页单独提供拖拽排序（工作台为改序入口）。

## 7. 迁移与兼容

- Flyway 新版本（建议 V10）：三张 rel 表 `ADD sort_order`；建 `asset_unlinked_order`。
- 已有关联行：`sort_order` 默认 0；首期可用 `asset.sort_order` 回填同分类子集，使初次进入筛选时顺序接近旧「全部」观感（可选，推荐做简单回填）。
- 旧客户端仍可调 `reorder`；新 UI 在筛选下改调 `reorder-by-scope`。

## 8. 验收标准

1. 「全部 + 无关键字」拖拽改序后，刷新仍正确；筛选视图顺序不被破坏。  
2. 选中具体人物，拖拽缩略图后刷新，该人物+该分类下顺序保持；切回「全部」时分类全局顺序未因该操作改变。  
3. 「无关联」、具体系列、具体篇章同理。  
4. 有关键字时可拖，刷新后顺序恢复为筛选规则下的持久顺序。  
5. 跨分类拖拽仍可用；失败回滚提示。  
6. `orderedIds` 与当前 scope 结果集不一致时接口拒绝，UI 回滚。

## 9. 非目标（首期）

- 搜索临时顺序持久化或「存为人物顺序」  
- 多选批量排序  
- 人物页内拖拽改序  
- 系列/篇章「未选具体目标」时的虚拟全集排序
